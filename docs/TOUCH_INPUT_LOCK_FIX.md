# 歌曲加载过渡期间触点残留修复

日期：2026-09-25。

## 现象与根因

用户反馈：进入歌曲加载画面前敲击鼓面，偶尔会使一次触摸卡住，进入游戏后的第一次敲击没有效果。

`src/libs/input.cpp` 的 `touch_event_watch()` 原先在检测到输入锁时直接返回。
这个判断同时跳过了按下、抬手和触摸取消事件，能够产生以下时序：

1. 锁定前收到 `SDL_EVENT_FINGER_DOWN`，把触点 ID 写入 `touch_id_to_vkey`。
2. 歌曲过渡动画启动，输入锁生效。
3. 锁定期间收到 `SDL_EVENT_FINGER_UP` 或 `SDL_EVENT_FINGER_CANCELED`，回调直接返回，没有删除触点。
4. 解锁后，系统如果复用了同一个触点 ID，下一次按下会被当成尚未释放的重复按下，不生成打击事件。
5. 这次敲击随后产生的抬手事件才清理旧记录，因此表现为第一次敲击无效、后续恢复。

切换场景和音频加载完成时调用的 `clear_input_buffers()` 只清理待消费的按键事件，
不会清理 `touch_id_to_vkey`。`reset_input_lock()` 也只重置动画锁计数，无法补回已经丢失的抬手事件。

上述事件时序已由直接调用实际触摸回调的测试复现；尚未用真机事件日志确认用户设备上的触点 ID 复用时序。

## 为什么本次保留输入锁

这不是音频解码或谱面解析所需的资源互斥锁，而是动画期间屏蔽操作的逻辑锁。

`Transition::start()` 启动全局动画 0–4。基础皮肤 `PyTaikoGreen` 的
`Graphics/global/animation.json` 为彩虹过渡动画 0 和歌曲文字淡入动画 3 配置了 `lock_input: true`，
由 `BaseAnimation` 管理输入锁计数。选曲到游戏以及游戏开场会使用这组动画。

当前代码仍依赖这个屏蔽行为：

- `GameScreen::update()` 等待异步音频加载时会提前返回，但解码结束后，即使过渡尚未结束，
  仍会调用 `Player::update()`，后者执行输入消费、鼓声音效、输入记录和音符判定。
- 双人和段位模式也在过渡尚未结束时更新玩家。
- `PracticeGameScreen::update()` 在过渡尚未结束时就调用 `global_keys_practice()`，
  处理暂停、跳转和其他练习操作。

因此，本次没有直接删除动画输入锁：单独删除会让这些操作在过渡画面仍遮挡游戏时生效。
如果未来要移除全局锁，应同时在场景层明确规定过渡期间允许哪些操作、何时消费或丢弃输入，
不能把底层停止跟踪触点当作操作屏蔽。这个场景输入重构不属于本次修复。

## 修复内容与影响范围

在 `touch_event_watch()` 中，把抬手和触摸取消处理移到输入锁的提前返回之前：

- 无论是否锁定，都删除对应的触点记录，并根据其他存活触点更新触摸状态。
- 锁定期间不向按键队列投递释放事件；新的按下事件仍被屏蔽。
- 未锁定时保留原有的按下、释放和重复按下去重行为。
- 触控配置关闭后收到旧触点的释放事件，也仍能清理记录。

修改位于共享 C++ 输入代码，覆盖使用该 SDL 触摸回调的平台，包括 iOS、Android 和桌面触屏。
没有改变键盘／手柄轮询、动画锁计数、歌曲时钟、判定窗口或音频缓冲；iOS 后台清理分支保留原有行为。
修复也适用于其他动画输入锁期间发生的触摸释放，不仅限于歌曲加载。
